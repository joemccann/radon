JWT audience claim not verified in FastAPI (verify_aud:False)
authn-authz · CWE-345: Insufficient Verification of Data Authenticity · patch: trivial · claimed low

Verifier: The code fact is accurate: scripts/api/auth.py:159 sets decode_options={"verify_aud": False}, so PyJWT does not validate the audience claim. But this is not exploitable against app.radon.run. The sub-based allowlist is STRICTLY STRONGER than an audience check: aud identifies the application, sub identifies the exact user. The finding's own threat model — a co-tenant token from a future demo.radon.run app on the shared Clerk instance — is the precise case the sub allowlist defeats, because such a token carries the attacker's own sub (not the operator's) and is rejected 403 regardless of aud. Recommendation: Add `"verify_aud": True` (or remove the key since True is the default) and pass `audience=os.environ.get("CLERK_AUDIENCE")` where CLERK_AUDIENCE is the Clerk application's publishable key. Clerk's JWKS response encodes the audience in the `aud` claim of issued tokens. This closes the cross-application JWT replay class entirely.
