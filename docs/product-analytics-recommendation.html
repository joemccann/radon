Module 01

Use PostHog Cloud. Do not deploy a generic tracking script.

Use

Curated product events

  • PostHog Cloud Free in the US region.
  • One project with user_mode=operator|demo; development and tests disabled.
  • Trends, funnels, retention, paths, and cohorts from a small typed event vocabulary.
  • PostHog MCP for read-heavy analysis from Codex and other trusted agents.
Do not use

Ambient surveillance

  • No autocapture, automatic full-URL capture, heatmaps, or replay in the operator app.
  • No client-supplied user identity or arbitrary event properties.
  • No Google Analytics as a second tracker. It adds noise, consent surface, and another taxonomy.
  • No self-hosted analytics workload on the production trading VPS.
High confidence
Why this wins: PostHog is the best combination of real product analysis, zero-dollar launch capacity, published spend controls, a first-party Codex-compatible MCP, HogQL, broad APIs, and a credible export/self-host escape route.1

Module 03

Put a privacy choke point between the application and the vendor.

Radon surfaces Normalized feature views from the client. Authoritative completion and failure events from server chokepoints.
→
POST /api/product-events Clerk-authenticated. Fixed event schema. HMAC pseudonym. Low-cardinality enums. Non-blocking delivery.
→
PostHog Cloud Trends, funnels, retention, paths, saved dashboards, MCP, HogQL, API, and exports.
Isolation boundary: Turso journal, portfolio snapshots, order events, raw assistant telemetry, broker errors, and operational logs remain first-party. They are not joined to or forwarded into PostHog.
Identity

Pseudonymous and personless

Derive a stable HMAC from Clerk userId on the server. Never send the raw ID, email, username, or avatar. Do not create PostHog person profiles at launch.

Reliability

Analytics fails open

A tracking timeout or vendor outage must never slow navigation, alter an API status, block an order, or mark a workflow failed.

Topology

Deployment-neutral

The same Next.js route works on the Hetzner operator app and Vercel demo. It avoids a remote CDN script and fits the current CSP.14

Module 04

Start with eight events. More data would make the system worse.

Event Authoritative trigger Allowed properties Question answered
feature_viewed Client route change after route normalization feature_id, entry_surface Which modules are reached, by whom, and how often?
workflow_started Explicit action, not component mount workflow_id, feature_id What are users trying to accomplish?
workflow_completed Server success response or verified client completion workflow_id, duration_bucket, result_count_bucket Which features deliver useful outcomes?
workflow_failed Sanitized server failure classification workflow_id, failure_class, duration_bucket Where does the experience break?
empty_state_seen Actionable empty or degraded state rendered feature_id, state_class, freshness_class Which modules look unused because data is unavailable?
recovery_action_selected User chooses retry, refresh, setup, or alternate path feature_id, action_id Do recovery controls work and get discovered?
assistant_turn_completed Assistant route after completion surface, outcome, latency_bucket, tool_count_bucket Is the assistant useful, fast, and reliable without exporting prompts?
execution_flow_advanced Server-side order workflow state transition stage, outcome, failure_class Where does the risk-review and execution flow lose users?

Global fields are server-owned: event_version, user_mode, deployment, release_sha, and pseudonymous distinct_id. Workflow IDs are controlled enums such as scan, watchlist_add, alert_create, workflow_run, order_preview, and assistant_turn.

Trading data: prohibited Ticker, strike, expiry, side, quantity, price, premium, P&L, NAV, margin, positions, order or account IDs, alert thresholds.
Identity and content: prohibited Raw Clerk ID, email, username, watchlist contents, bookmarks, assistant prompts or answers, workflow graphs, broker messages.
Ambient capture: prohibited Full URLs, query strings, DOM text, screenshots, console logs, network bodies, replay, free-form errors, arbitrary client properties.
Module 05

Build dashboards around decisions, not vanity counts.

Saved view Definition Initial action rule
Feature adoption Unique users per feature_id divided by weekly active users, with operator and demo split. Investigate features below 5% of WAU for six weeks before investing further.
Useful workflows workflow_completed / workflow_started, by workflow and release. Fix any material workflow below 70% completion or down 10 percentage points from its four-week baseline.
Friction register Failures, empty states, recovery attempts, and P50/P90 duration by feature. Work the highest-volume recoverable failure first. Do not rank by anecdote.
Time to first value First authenticated session to first completed high-value workflow. If P90 exceeds two sessions, repair onboarding, empty-state guidance, or navigation.
Retention by first value Week-1 and week-4 return rate grouped by the user's first completed workflow. Promote entry paths associated with persistent retention lift; treat correlation as directional until tested.
Release impact Completion, failure, and duration before and after release_sha. Reopen a shipped change when completion falls and the effect survives normal traffic variation.
Sample discipline

If a cohort has fewer than 20 users, label the result directional and inspect event sequences or conduct interviews. Do not manufacture statistical certainty from a small demo population. Recalibrate every threshold after 30 days of real baseline data.

Module 06

A four-stage rollout that produces useful evidence in the first week.

Stage 0 / Before code

Set the data contract

Create one PostHog US Cloud Free project, set the billing limit to $0, disable session replay and autocapture, leave AI data processing off initially, and publish accurate app/demo privacy notices before collection begins.

Stage 1 / Foundation

Build the typed gateway

Add a same-origin authenticated endpoint, server-owned HMAC identity, event/property allowlists, route normalization, timeout isolation, production-only gating, and regression tests for every prohibited field class.

Stage 2 / First signal

Instrument reach and outcomes

Ship feature_viewed, workflow start/completion/failure, empty states, recovery actions, assistant outcomes, and execution stages. Record server-side success only at authoritative chokepoints.

Stage 3 / Day 30

Close the product loop

Connect the MCP to a trusted local agent, create the six saved views above, run the weekly decision prompt, delete noisy events, revise thresholds, and decide whether a demo-only fully masked replay pilot is justified.

A captured-event sample contains zero prohibited values or keys.
Development, test, and unauthenticated traffic emit zero events.
Vendor failure changes no product response, latency budget, or order state.
Dynamic ticker routes resolve only to controlled feature IDs.
Operator and demo views are separated in every saved report.
An agent can answer the six product questions without person-profile access.
Module 07

Make the agent an analyst, not an unsupervised product manager.

Weekly analysis prompt

Copy this into Codex through PostHog MCP

Analyze Radon product usage for the last 28 days.

Return: feature -> reach -> workflow completion -> friction -> recommended action.

Compare operator and demo separately. Use only saved views and allowlisted fields. Label cohorts under 20 users as directional. Identify features below 5% WAU for six weeks, workflows below 70% completion, and material release regressions.

Do not request person profiles or raw events. Do not create or modify dashboards, flags, experiments, surveys, or cohorts. Cite every claim with the query and sample size.
Agent policy

Read-heavy by default

  • Allowed: query saved insights, execute bounded HogQL, compare cohorts, summarize release impact.
  • Approval required: create or edit dashboards, cohorts, flags, experiments, or surveys.
  • Forbidden: person-profile lookup, session replay, raw event export, joining analytics with trading records.
  • Evidence floor: query, date range, cohort size, and uncertainty accompany every recommendation.
Fallback rule
Move to Amplitude only if the 2M free-event ceiling or its analyst interface becomes decisive. Move to OpenPanel if a vendor-enforced read-only MCP credential becomes mandatory. Self-host only under a real data-residency requirement, and place it on separate infrastructure.
