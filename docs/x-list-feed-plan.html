00 Counterpoint first

Do not romanticize realtime

“Realtime X list next to Market Ear” is not small UI glue. There is no native list firehose. True push means filtered-stream rules rebuilt from membership (or Enterprise). For one operator list, poll + Turso + 1–2 min UI refresh is the correct product, not WebSockets. Scraping X is a non-starter for production. xAI x_search in-repo is watchlist research, not a list timeline. Confidence high

List ID from URL: 1240684211385675777. Confirm public with GET /2/lists/{id}?list.fields=private before locking auth. ID parse high Public status moderate until verified

03 Hard requirements

Product

  1. Follow one fixed list (constant + env): X_LIST_ID=1240684211385675777.
  2. Show new posts: author, text, time, link to https://x.com/{user}/status/{id}, optional media.
  3. Placement: inside left feed rail (tab or stacked panel) on first ship.
  4. Operator app only (Clerk); not demo-mirrored unless product asks later.
  5. Empty / degraded states describe measurement conditions (token missing, list private, poll stalled).

Technical (Radon rules)

  1. No spawn from Next.js. Producer is daemon/timer; Next only reads Turso.
  2. Turso-first; migration required; optional JSON fallback.
  3. Secrets in .env / Hetzner ~/radon-cloud/.env only.
  4. Brand tokens only; instrument-module chrome; no em dashes; no Twitter product chrome.
  5. service_health for the poller; register staleness windows.
  6. TDD: parse + API + panel; Playwright for tab presence.

Legal / platform

  1. Official X API v2 only for production.
  2. Display + offline cache with content compliance (delete when post is deleted/protected).
  3. Prefer hotlink media URLs; do not rehost unless justified.
  4. Developer app use case: private operator dashboard, not redistribution.

04 Architecture decision

ChoiceDecisionWhy
Transport Poll GET /2/lists/:id/tweets Native list timeline; 900 req/15 min; simple
Cadence 60–120 s producer + UI poll Matches Market Ear “live”
Auth OAuth 2.0 App-Only Bearer Public list read
Billing Pay-per-use credits (~$0.005 / post read, 24h dedupe) New access is PPU; legacy Pro closed/migrating
Stream Out of v1 No list-native stream; member from: rules = churn + cost
Scrape / Nitter / unofficial Forbidden ToS + reliability
xAI x_search Not the producer Wrong product surface

Cost sketch

Poll every 2 min → 720 calls/day. Billing is mostly unique posts, not raw HTTP. Quiet list: cents to low dollars/day. Set a hard credit cap.

Confidence

Poll high · PPU unit prices moderate — confirm in console before budgeting.

P2 — Spec (docs/x-list-feed.md)

  1. Freshness SLA: posts appear ≤ 3 min after X publish under normal limits.
  2. History: last N days or last M posts (e.g. 7d / 500 rows).
  3. Layout A (recommended): tabs inside feed: MARKET EAR | X LIST. Alt B: stacked panel under Market Ear.
  4. Payload (canonical):
{
  id: string;              // tweet id
  text: string;
  created_at: string;      // ISO
  author_id: string;
  author_username: string;
  author_name: string;
  author_avatar_url?: string;
  media?: { type: string; url: string }[];
  urls?: { display: string; expanded: string }[];
  metrics?: { like_count?: number; retweet_count?: number };
  list_id: string;
  ingested_at: string;
  deleted?: boolean;
}

Request fields: tweet.fields=created_at,author_id,public_metrics,entities,attachments,note_tweet · expansions=author_id,attachments.media_keys · user.fields=username,name,profile_image_url · media.fields=url,preview_image_url,type · max_results=100 + since_id for catch-up.

P3 — Storage

New table x_list_posts (next free migration):

  • PK id (tweet id)
  • list_id, created_at, author_*, text, payload JSON, ingested_at, deleted
  • Indexes: (list_id, created_at DESC), deleted
  • Optional scan_snapshots service x-list
  • Writer: chunked upsert; never empty-wipe on failed poll

Out of scope v1: likes UI, posting, DMs, multi-list.

P5 — API + hook

  • Route: GET /api/x-list/posts — Clerk, force-dynamic, Turso, missing = 200 + empty
  • Cache: short max-age or no-store (like newsfeed)
  • Hook: useXListPosts — poll 60–120s, last-good hold
  • Tests: empty, rows, no cross-table leak

P6 — UI

  • Component: DashboardXListFeed (+ tab shell if chosen)
  • Wire into DashboardSurface feed section
  • Row: handle, relative time, text (no em dash), media thumb, open-on-X
  • Meta rail: source X LIST, list id/name, last poll time
  • Empty: “No list posts yet. Waiting for the x-list poller.” / “X API token missing.”
  • Mobile: same stack; tabs over dual sticky rails

Never hardcode “Refreshes 60s” unless it matches timer + hook.

P7 — Compliance and ops

  1. Periodic GET /2/tweets?ids=…; mark deleted if gone.
  2. Retention prune (weekly).
  3. Hetzner install timer once (deploys do not enable new units).
  4. Cloud runbook blurb.
  5. Demo: exclude unless product asks.

P8 — Verification

  1. Fixture parse tests green.
  2. Live poll inserts Turso rows.
  3. Authenticated API returns them.
  4. Dashboard shows rows; screenshot.
  5. Kill token → empty/error, not 500 cascade.
  6. CI green after merge.
