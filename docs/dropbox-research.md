## Components and data boundary

- `research.publish`: validated assets and atomic `posts` plus `research_post_sources` writes over bounded Turso HTTP. Reserved `research-` IDs remain idempotent across outbox retries. No competing posts.json writer.
- Private files live in `RADON_RESEARCH_DIR/assets`, default `/var/lib/radon/research/assets` inside containers, outside public media. The host bind source is `/var/lib/radon-private/research`, beneath a root-owned `0700` anchor; the child is owned by radon with mode `0700`. The MarketDesk and research archive units mount it read/write; the API mount is read-only. The authenticated Next route bypasses image optimization and caches. Research rows are excluded from demo reads and the public demo mirror.

## Database transport idle expiry

Both bounded Turso HTTP transports (`api.db_http` and `db.hrana_http`) retire a pooled connection before sending the next request when it has been idle for at least five seconds. Idle age uses a monotonic clock stamped after the complete successful HTTP response body is read. Closing a failed, oversized or non-200 response clears that clock; changing origins also closes the previous connection. This protects the outcome-mirror write after a long model review from reusing an expired socket. Recent requests still reuse their connection. Existing conservative read-only reconnect rules remain unchanged, and a write with an uncertain outcome is never replayed automatically.

## Clairic report dates (off by default)

`CLAIRIC_DATES_ENABLED=1` asks `@cf/cloudflare/clairic` for `report_date` before the ladder. The request is one REST call to `https://api.cloudflare.com/client/v4/accounts/{CLOUDFLARE_ACCOUNT_ID}/ai/run/@cf/cloudflare/clairic` with pages 1-3 plus the last page, capped to one 8,192-token pass, and a 10 second timeout. `publisher` is included only when it fits in that same pass. Stdlib `urllib` is the client; no extra dependency is pinned. A date is kept only when `confidence` is at least 0.9 and it is not in the future (America/New_York) and not more than 45 days before the Dropbox folder date. Otherwise the ladder runs. A successful Clairic response also applies that 45-day check to the ladder result, and a failure there stores the folder date. `CLAIRIC_DATE_SANITY_ENABLED=1` applies the same 45-day check to the ladder with Clairic left off. Both flags default off (`1` is the only on value), and off is the current ladder with no `date_flag` key. A timeout, HTTP error, or missing `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_API_TOKEN` logs one `clairic_date` line and leaves the ladder date as it is today. `date_flag` (`clairic_low_confidence`, `stale_vs_folder`, `future_date`, `no_printed_date`) is stored on the identity block and on `research_outcomes.context_json`. It is not a hold reason.

Credentials are the same host file as the other radon-research API keys: `/etc/radon/env` (root:radon 0640, unquoted `KEY=value`), loaded by the MarketDesk units. They are not required keys. Provisioning, rotation, and the `mcp.env` / newsfeed allowlist exclusion: [Environment handling](../cloud/CLAUDE.md#environment-handling).

## Operator feedback loop

Research feed cards carry thumbs up/down with reason chips and an optional comment (`web/components/ResearchFeedback.tsx` → `POST /api/newsfeed/research/feedback`, operator-only, Turso `research_feedback`, append-only, latest vote per target wins). A thumbs-down retracts the post from the feed without altering the post row; a `clear` vote restores it. Every reviewed document mirrors its outcome, reason codes and rejected drafts to Turso `research_outcomes` (`research.publish.record_outcome`), which feeds the Held tab: a daily sample of ten held or dropped documents whose `updated_at` (process time, America/Los_Angeles clock) is within 24 hours, excluding `HELD_EXPIRED`. A fresh `held` decision sets `held_at`; repeated writes while the row remains actively held preserve that value and cannot extend its 24-hour TTL. A transition back to held after a dropped, published or expired decision starts a new hold clock. Every newly recorded decision clears the previous `expired_at`; non-held decisions retain the historical `held_at`. The MarketDesk job expires held rows older than 24h (`held_at`, else `updated_at`) to `dropped` + `HELD_EXPIRED` and sets `expired_at` without changing `updated_at` (`publish.expire_stale_held`, called from `research.marketdesk_job` beside `feedback.apply`); it never republishes or requeues. Rows flagged `alwaysPublish` (Citadel Rubner GMI) or whose excerpt still matches that desk are left held. The daily Dropbox PDF cut is `PYTHONPATH=scripts python3.13 -m research.cut_report --date YYYY-MM-DD` from the repository root (default yesterday PT when `--date` is omitted) or the `workflow_dispatch` workflow `.github/workflows/research-pdf-cut.yml` (runs only from `main`; its public artifact is `--counts-only`, with no document names or work keys). Day assignment: published, held, and dropped rows use decision time (`updated_at`). Hold-expired rows use `expired_at` (fallback `updated_at` for legacy rows). Hold-expired rows are also listed under the day they were originally reviewed or held when `held_at` is known. Buckets: published; held (still held); hold expired (24h TTL); dropped. Hold-expired is never labelled "retries exhausted". The operator marks "Should have published" or "Correct to hold". The review consumer polls votes every `FEEDBACK_POLL_SECS` (`research.feedback.apply`): a "should have published" vote, or a thumbs-up with "want more", re-queues the document ahead of the backlog with the operator's note. The note reaches SELECT as `OPERATOR NOTE`, overrides a triage drop, and for "want more" asks for one revised candidate that replaces the existing post in place (same post id; the post under revision is excluded from the novelty comparison). Handled vote ids live in the local queue (`feedback_handled`), so an action runs once; a fetch failure changes nothing. The same poll feeds `research.learn`: every vote becomes a worked example in `<root>/examples.json`, and SELECT receives the twelve most similar ones as `OPERATOR PREFERENCES` (verdict, reasons and the operator's comment; lexical similarity with a series and publisher bonus). Hard rules are never automatic: a series with three rejections (publisher or document type with six) and no approval becomes a row in Turso `research_rule_proposals`, shown at the top of the Held tab with Approve / Reject; the job only inserts or refreshes counts and never writes `status`. Approved rules are cached in `<root>/rules.json` and applied by `triage.decide(rules=...)` with reason codes `SERIES_DENYLIST`, `RULE_DOC_TYPE`, `RULE_PUBLISHER`. Reject and Revoke move a rule to the Rejected list on the Held tab, where Approve reactivates it; rejected history is listed.

## Model calls

### Model ladder (shared HTTP)

Default text order: Antigravity, Anthropic, Grok, Cursor, Codex, NVIDIA, Cerebras. Quota or unavailable-provider responses advance to the next available rung. Image requests retain their images and skip the text-only Antigravity CLI.

New multimodal or text-JSON model callers must use `scripts/clients/model_ladder.py` (import `complete_text_json`, `complete_multimodal_json`, or `extract_via_vision`). Text-JSON and CTA vision HTTP responses stream through a 2,000,000-byte cap and close before parsing on Anthropic, Grok, Codex, NVIDIA, and Cerebras. The Antigravity CLI refuses images, so vision skips that rung, and its text stdout is not under this HTTP cap. Do not add a third cascade. `scripts/clients/vision_cascade.py` is a thin re-export for CTA/MenthorQ. The newsfeed text tagger reaches the same helper through `scripts/clients/model_ladder_cli.py`. Nightly CLI sessions are owned separately by the [agent runner](runner.md).

A rung fails over on a non-2xx status or on a 2xx body that is a provider error envelope (top-level `error`, or `type: "error"`). Credit, quota and billing markers are matched only against that envelope or a non-2xx body, never against a successful answer: research and distill copy routinely says "capacity", "quota" or "billing", and matching it once failed every rung on the same document.

#### Auth matrix (research / CTA / knowledge / newsfeed)

Knowledge distill (`scripts/knowledge/distill.py` → `complete_text_json`) and the newsfeed tagger (`model_ladder_cli.py`) share this ladder with research review and CTA vision. Subscription-tier rungs (Anthropic / Grok / Codex / Antigravity) use **subscription credentials only** — prepaid console keys are never read or sent, under any flag (operator policy 2026-10-26). Inject secrets via `/etc/radon/env` (mode `0640` `root:radon`); never commit values. Composer is the coding agent, not a ladder rung. Cerebras stays wired as the last rung on Hetzner and spends whatever credit the account has; once it is exhausted, the ladder is exhausted. `radon-knowledge.timer` runs hourly ([knowledge embeddings](knowledge-embeddings.md)).

**NVIDIA rate limit.** The key is free but limited per key (about 40 requests a minute). Production inference paces inside the model gateway. The runtime forces the serving state file to `/var/lib/radon/model-cache/nvidia-rate.json`. A host `RADON_NVIDIA_RATE_STATE` value is not that file. `RADON_NVIDIA_RPM` still defaults to 20. When no slot frees within `RADON_NVIDIA_LADDER_MAX_WAIT_S` (default 15 s) the rung is skipped as `nvidia:rate_limited_local` and nothing is sent. A 429 starts a 30 s cooldown and falls through without retrying in place (and without trying the vision fallback model); five in a row, or any 401/403, pause NVIDIA for 15 minutes. A 401/403 logs `NVIDIA AUTHORIZATION FAILED` at ERROR. Every non-200 failure logs its status and a redacted body excerpt (at most 200 characters). Injected test `post=` callables are never paced. Do not clear a trip by editing a home-directory copy. Details: [model-gateway.md](model-gateway.md) and [runner.md](runner.md#nvidia-rate-limits).

Cerebras is the last resort in every order, including a caller's `providers=` override: `_run_ladder` moves it to the end, so nothing is tried after it and its failure exhausts the ladder. `scripts/tests/test_cerebras_last_rung.py` pins this for the shared, CTA vision and SLM tagger orders and for the nightly loops' `fx:cerebras` rung.

The order is `MODEL_LADDER_ORDER` in `scripts/model_gateway/contracts.py` (Antigravity, Anthropic, Grok, Cursor, Codex, NVIDIA, Cerebras). Callers may pass `providers=`; unknown names are ignored. There is no env override of that tuple. Grok is xAI via the existing `~/.grok/auth.json` grant (`XAI_MODEL` / `GROK_MODEL`). Antigravity is the documented `agy -p` CLI only (text; images record `image_unsupported` and the ladder continues). There is no separate Google HTTP API on this rung.

Anthropic replies are read from every `text` block, including a list of text spans, and from a Messages SSE body when the HTTP body is not one JSON document. Thinking blocks are not the answer. The gateway client (`scripts/clients/model_ladder.py`) raises `ModelResponseError` when the gateway reports an incomplete or invalid reply, for every caller. A reply the caller's `accept` rejects resumes the next rung through the gateway continuation.

Provider cooldowns live on the [model gateway](model-gateway.md): a named-reset 429 and a spent quota at any status both persist via `clients.provider_cooldown` (`RADON_PROVIDER_COOLDOWN_STATE`, default `~/.radon/provider-cooldown.json`, capped at 7 days). Later calls in that window, including a new oneshot process, record `<provider>:rate_limited_cooldown` and send nothing. A bare 429 persists nothing: that request moves to the next rung and the next call tries the provider again.

NVIDIA calls `https://integrate.api.nvidia.com/v1/chat/completions`. A 404 or 400 on one model continues to the next NVIDIA model, then the next live rung. Cerebras 413 is `http_413` and continues; the gateway does not skip a request from an image-count or body-byte env cap.

A host without subscription grants skips those rungs. `engine.PAUSED_BY_DEFAULT` still pauses NVIDIA and Cerebras even when keyed, so the ladder is exhausted rather than falling through to those keys. Prepaid keys never wire subscription rungs. Mount subscription tokens for fuller band coverage.

**Expired subscription token.** When a subscription rung (Anthropic / Codex / Grok / Antigravity) answers 401 with an expired-token body, the ladder runs one `subscription_tokens` pass for that provider under the timer's run lock (no push login, no heartbeat), re-reads the credential and retries the same model once before falling through. The timer's refresh lead is the [subscription token owner](subscription-tokens.md). This retry is the backstop.

Auth-file API keys are never read either: a Codex auth.json API key and Grok
`api_key`, `apiKey`, or `credentials.api_key` do not wire a rung. Codex
`auth_mode=apikey` also prevents stale OAuth fields in that file from being
selected. Supported OAuth access
token fields remain subscription credentials.

### Subscription stream completion

Subscription Responses streams must carry a `response.completed` event whose
response status is `completed` before the shared Python ladder or web adapter
accepts text. EOF, failed/incomplete events and malformed terminal data discard
partial output, including otherwise valid reviewer JSON. Failure messages omit
provider payloads; configured provider fallback remains available. Python keeps
its existing byte limit and response-close guarantee; the web adapter consumes
the response body before validating completion.

## Hosted Nemotron defaults

Nemotron 3.5 Super VL is the default NVIDIA vision model and Nemotron 3 Ultra the default text model (2026-11-01), because the prior defaults were not callable on the production key. Only those two NVIDIA ids receive `reasoning_effort: none` and API `stream: false`; the Llama 90B fallback and other providers receive neither. Transport reads remain bounded and existing JSON/grounding validators remain authoritative. Provider order and embeddings do not change. The [pilot quality gates](nemotron-super-vl-pilot.md) were not run before promotion. `RADON_RESEARCH_MODEL` does not select NVIDIA image models.

## Final copy certificate

`research.publish` refuses any research post without a valid Humanizer certificate for the exact final rendered copy and validates it immediately before the database transaction. The rubric lives in `research.humanizer`, so production does not depend on a user's home-directory skill files. MarketDesk obtains the certificate in `research.marketdesk_copy` ([MarketDesk research](marketdesk-research.md)); the gate itself is owned by the [generated-copy Humanizer](generated-copy-humanizer.md) page.
