Stop market and stop limit on positions

Feasible on the existing TWS API path. No new broker SDK. Placement is hardcoded to limit; the SDK already knows both stop types.

Verdict: ship API: STP + STP LMT SDK: StopOrder / StopLimitOrder UI + place funnel only

01Verdict

  • IBKR supports both types on the Gateway/TWS socket Radon already uses.
  • Do not switch to Client Portal REST. Campus documents the same fields there; Radon does not use that API.
  • Work is schema, constructor, and ticket UI. Contract qualify, permId poll, halt, idempotency, and open-order display already exist.

02IBKR contract

User termIB orderTypeFieldsProducts
Stop market STP auxPrice = trigger. No limit. STK, OPT, FUT, FOP, BAG, CASH, CFD, WAR
Stop limit STP LMT auxPrice = trigger, lmtPrice = cap after trigger STK, OPT, FUT, FOP, CASH, CFD, WAR. Not BAG.
  • Sell stop must sit below last. Buy stop must sit above last. Else IB error 110.
  • Long: SELL stop. Short: BUY stop. Qty should not exceed the position.
  • STP guarantees a send, not a price. STP LMT can miss if the print gaps through the limit.
  • GTC is the right TIF for a resting protective stop.
  • outsideRth is off by default. Stops do not fire after hours unless set.
  • triggerMethod default 0 (Last). Leave default in v1.
  • Existing position: standalone order, parentId=0. Bracket parentId only applies to a still-live parent.
  • Sources: IBKR Campus Stop / Stop Limit; TWS basic_orders; Radon docs/ib_tws_api.md.

03SDK already in use

Python 3.13, ib_insync==0.9.86, Gateway port 4001 via IBClient. Verified constructors:

StopOrder(action, qty, stopPrice)           # orderType='STP',     auxPrice=stop
StopLimitOrder(action, qty, lmt, stopPrice) # orderType='STP LMT', lmtPrice + auxPrice
IBClient.place_order(contract, order)       # accepts any Order
IBClient.place_bracket_order(...)           # unused by the web ticket
  • Open-order sync already returns orderType and auxPrice (scripts/ib_orders.py).
  • Modify already allows LMT and STP LMT limit price. STP trigger (auxPrice) is not wired in the modify route.
  • Paper matcher already fills STOP vs last. Demo path needs the same body fields.

05How to add it

  1. Extend place body: orderType: LMT | STP | STP LMT, stopPrice required for both stops, limitPrice required only for LMT and STP LMT.
  2. In ib_place_order.py branch the constructor. Keep qualify, halt, fat-finger, permId poll, and combo NonGuaranteed unchanged.
  3. order_limits: notional from limitPrice if set, else stopPrice. STP still needs a dollar cap.
  4. UI on the position ticket: type STP / STP LMT, stop field, optional limit offset, default qty = |position|, side inferred from long/short.
  5. Modify: allow auxPrice on STP and STP LMT. Today only lmtPrice moves.
  6. Paper: map STP to existing STOP. Add stop-limit as trigger then limit match.
  7. Tests first: red on STP without limitPrice, green through script + route + ticket payload. Playwright on the position ticket.
# long 100 AAPL, stop market 170
{"type":"stock","symbol":"AAPL","action":"SELL","quantity":100,
 "orderType":"STP","stopPrice":170,"tif":"GTC"}

# same, stop limit 170 / 168
{"type":"stock","symbol":"AAPL","action":"SELL","quantity":100,
 "orderType":"STP LMT","stopPrice":170,"limitPrice":168,"tif":"GTC"}

Reuse POST /orders/place. Do not add a second placement script. What-if already takes any Order object.

07Risk notes

  • Option STP in a fast tape can print far through the trigger. Prefer STP LMT on options unless the operator wants a guaranteed send.
  • A stop is not reduce-only at IB. Oversized qty opens a reverse position. Cap qty at |position| server-side.
  • Two overlapping sells on the same long is the exit_orders double-place class of bug. Scan open orders for same conId + SELL before place.
  • The 40% far-from-market reject is a limit rule used by the exit daemon. Stops use trigger-vs-last, not that band.
  • Do not treat journal or portfolio stop as working protection. If it is not in IB open orders, it is not live.
