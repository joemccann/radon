Provider API contract

The page is an indexed strike-by-expiration cube

The provider response contains strikes, expirations, spot, timestamp, and flattened cells that reference strike and expiration indices. Radon validates the shape, indices, finite numbers, duplicate cells, and provider identity before returning normalized data to the browser.

# Primary exposure cube
GET gateway.menthorq.io/clickhouse-api/api/web/v1/options/net-gex-by-expiration/MU?frequency=eod
GET gateway.menthorq.io/clickhouse-api/api/web/v1/options/net-gex-by-expiration/MU?frequency=intraday

# Levels and supporting page calls
GET gateway.menthorq.io/.../gamma-levels/MU/eod
GET .../tickers/MU/last-updated
GET .../options/matrix/MU?frequency=intraday
GET .../prices?tickers=MU
Normalized fields

symbol, frequency, source_timestamp, spot, strikes, expirations, and flattened cells containing net_gex, abs_gex, net_dex, abs_dex, oi_call, and oi_put.

Unit handling

Provider GEX is normalized from USD billions per 1% move to USD using value × 1e9. DEX stays USD. Open interest remains contract counts. For the center OI exposure bar, Radon computes call OI − put OI.

Authentication boundary

Radon retains credentials and session material on the server

The browser only requests Radon’s local API. It never receives the provider’s cookies, refresh tokens, ID tokens, or Bearer access token.

  1. 01

    Dashboard redirect

    An unauthenticated exposure request routes to the WordPress login with a Cognito callback.

  2. 02

    Server-side WordPress login

    Radon enters the existing credentials only in its server-side browser context.

  3. 03

    Session retrieval

    The returned dashboard session yields a current Cognito access token.

  4. 04

    Validated provider request

    The server validates and normalizes the provider cube before returning its typed payload.

  5. 05

    Sanitized browser payload

    The browser receives exposure data or a bounded 400, 503, or 504 state.

Operational next step

No manual token provisioning is required while the existing WordPress credentials remain valid. The client refreshes its dedicated dashboard.menthorq.io state owner-only; an explicit short-lived MENTHORQ_DASHBOARD_ACCESS_TOKEN remains available for operational override.
