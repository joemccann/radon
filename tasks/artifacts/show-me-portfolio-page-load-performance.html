Priority register

Six changes account for most of the recoverable load cost.

Priority reflects direct critical-path evidence, not a generic performance checklist.

P0F-01 / Cold state

Let the initial GET settle before blackout recovery can POST.

Render a usable GET snapshot immediately. Only trigger producer recovery after the initial read finishes and proves missing or stale. If a background sync runs, it must not invalidate an already successful snapshot response.

  • Regression: fast fresh GET plus delayed POST must paint GET data first.
  • Recovery: missing GET must still arm the producer sync.
  • Stale data: paint the stale snapshot with warning provenance while refresh runs.
P0F-02 / API payload

Remove orders-only entry-date maps from /api/portfolio.

The default response waits for two journal-wide JSON scans after the indexed snapshot lookup. The portfolio UI does not read either map; only the executed-order share path does.

  • Snapshot payload: 11,194 B.
  • Merged response: 25,565 B.
  • Move maps to an orders-only endpoint or an explicit include mode.
P0F-03 / JavaScript

Split the 4,193-line all-routes workspace module.

WorkspaceSections is one delayed chunk, but it statically imports portfolio, orders, scanner, regime, admin, workflow, profile, options, ticker, mobile, and performance code before switching at runtime.

  • Dynamic chunk: 1,198,604 B raw / 248,220 B brotli.
  • Cold route JavaScript: approximately 448 KB brotli.
  • Create statically analyzable route-specific imports and a compressed budget.
P1F-04 / Navigation

Stop viewport prefetching the entire workstation during cold load.

Visible sidebar links initiated 21 unrelated RSC requests across two waves while the current route was loading. Disable automatic prefetch for the fixed rail, then prefetch on focus or pointer intent.

P1F-05 / Data boundary

Start the snapshot on the server, not after hydration.

app/portfolio/page.tsx renders only the client shell. The first portfolio read began around 136 to 146 ms after navigation in local production traces. A dynamic Server Component boundary can pass initial data into a narrow client surface, while no-store polling continues for updates.

P1F-06 / Background work

Defer and deduplicate noncritical shell work.

The cold shell starts profile, service health, flex token, orders, relay health, two sockets, optional quote fallbacks, and up to three identical risk-free-rate requests. Keep the portfolio snapshot first.

  • Use one client in-flight cache/provider for the daily risk-free scalar.
  • Defer footer detail and closed overlays until after primary paint.
  • Route-scope quote subjects; share one relay connection manager.

Cache policy

Coalesce work without making trading data stale.

HTTP freshness and application-memory coalescing are separate decisions.

Keep Live-data boundaries

  • /api/portfolio, orders, watchlist, health, tickets, and realtime data remain force-dynamic where required and no-store in the client and response.
  • Service worker continues to bypass navigations, RSC data, /api, and /ws.
  • Static hashed JavaScript already sends one-year immutable caching.
  • Direct-to-cloud remains the default; do not reintroduce data/replica.db.

Add Safe coalescing

  • Persist the last successful portfolio snapshot in a client provider or module store, paint it immediately, then no-store revalidate.
  • After removing entry maps, raise the server snapshot coalescing TTL from 3 s toward 15 s and measure.
  • Wrap the combined orders read in a 2 s single-flight cache, invalidated on order mutations.
  • Cache the daily risk-free scalar with bounded server revalidation and a client in-flight promise.

Method and constraints
  • Built the current checkout with next build --experimental-build-mode=compile and served it with next start.
  • Used controlled API responses to isolate browser ordering, bundle loading, request initiation, and the GET/POST generation race.
  • Ran read-only production Turso queries and EXPLAIN QUERY PLAN; no IB actions or database writes were performed.
  • Chrome DevTools trace tooling was unavailable, so Playwright Performance APIs and build artifacts supplied the browser evidence.
  • Measurements from the development Mac include local topology and are not substituted for VPS TTFB or field p75 metrics.
Regression tests required with implementation
  • Fast fresh GET plus delayed POST: rows paint from GET; POST cannot invalidate them.
  • Missing GET: producer recovery still fires once under shared cooldown.
  • Base portfolio GET: exactly one snapshot query and no journal SQL.
  • Cold browser: one initial portfolio GET, no automatic POST for a fresh snapshot, zero unrelated RSC viewport prefetches.
  • Bundle contract: portfolio no longer references the omnibus workspace chunk and stays below an agreed compressed budget.
  • Orders coalescing: concurrent GETs share one parallel pair of statements; mutations invalidate the entry.
