## Blockers and implementation risks

- Public plate remediation requires removing/replacing deployed assets and purging CDN/repository history; source edits alone do not retract prior disclosure.
- Demo-mirror remediation requires a one-time purge of production-derived rows in the demo database in addition to removing the table from the allowlist.
- Durable per-principal limits and cross-process single-flight need an available shared store; production/demo must fail closed if that dependency is required but absent.
- Route-local auth must preserve explicit public preview/webhook/probe contracts and distinguish operator from active-demo capabilities; a blanket operator-only guard would break demo-safe reads.
- Service/unit changes require deployment-time permission migration for existing backups, logs, browser state, and state directories.
- Assistant prompt-injection risk cannot be eliminated by delimiters alone; deterministic tool authorization and caller-intent binding are required even after isolated extraction.
