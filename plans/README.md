# Animation improvement plans

Generated by `improve-animations` against commit `78bcf138`. Motion in this app is plain CSS/WAAPI (no library), concentrated in `web/app/globals.css`. Personality per `docs/brand-identity.md §6`: crisp dark trading terminal — motion "slow, analytical, confidence-increasing, not flashy." A global `prefers-reduced-motion` reset already exists (`globals.css:174`), so accessibility is broadly covered; these plans respect it.

Each plan is self-contained: exact file:line, verbatim current code, exact target values, and a feel-check. An executor with zero context can run any one in isolation.

## Execution outcome (2026-07-15, from commit 78bcf138)

All 8 applied, verified: `tsc --noEmit` clean, full Vitest suite green. 001 additionally preserved existing press-scale by adding `transform`/`opacity` to the buttons that animate on `:active`. 005 shipped as a keyframe `opacity`+`translateY` reveal after the `@starting-style`/`grid-rows` variant proved fragile in live verification. 007's pre-existing press-scale block was narrowed to primary/destructive/order-entry controls only (tabs/chips/utility no longer scale), and the now-inert `transform` was stripped from their transitions.

## Recommended execution order

Ordered by leverage (impact ÷ effort), with dependencies respected:

1. **001** — highest leverage: one token, kills 13 copies of the canonical anti-pattern on high-traffic controls. Trivial, zero visual regression risk in dark theme.
2. **002** — trivial, high-visibility: the 2.5s flash is seen on every tick. Two-line change.
3. **007** — additive tactility on the buttons users click most. **Do after 001** (reuses the `--transition-controls` token).
4. **006** — removes the "toast vanishes/jumps" break. Self-contained JS+CSS.
5. **003** — GPU-driers the regime/strength/flow bars. Touches `RegimePanel.tsx`.
6. **008** — same pattern as 003 for the seasonality bar. **Do after 003** (mirror its scaleX approach).
7. **004** — low-leverage layout-anim removal; default path is a one-line delete.
8. **005** — lowest leverage; fixes a latent `max-height: 40px` clip. May need a small markup wrap; STOP-guarded if the banner markup isn't a clean single child.

## Dependencies

- **007 depends on 001** — it appends `transform` to the `--transition-controls` token those buttons use. 007 includes a fallback if 001 isn't applied.
- **008 mirrors 003** — do 003 first so 008 copies an in-repo exemplar. Not a hard dependency.
- All others are independent and can be done in any order.

## Notes / open feel-checks

- **002** and **004** have outcomes that can't be judged from code alone (does the flash stack under fast ticks; is the instant tape toggle jarring). Their plans put the decision in a feel-check step with concrete acceptance criteria and fallback values.
- **003 / 008** STOP-guard if a bar's dynamic-width source isn't a simple inline percentage, or if a track isn't full-width — do not let the executor guess.
- **005** STOP-guards if the banner markup can't cleanly get a single content child.

## Not planned (deliberately)

- Entrance keyframes (`modal-slide-up`, `mobile-sheet-in: translateY(100%)`, `watchlist-enter`, `chat-msg-in`) are already correct — `translateY` + `opacity`, no `scale(0)`, on-brand durations. No change.
- The `--ease-out: cubic-bezier(0.25,1,0.5,1)` token is a reasonable custom curve; not relitigated.
- Per-component `prefers-reduced-motion` handling — the global reset covers it.
