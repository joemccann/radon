Radon Cloud Deployment Guide

Migrate app.radon.run from Vercel to a self-hosted Hetzner VPS

Goal: Move the Radon trading terminal from Vercel (Next.js only) to a single Hetzner VPS running the full stack — Next.js, FastAPI, WebSocket relay, IB Gateway, monitor daemon, and data refresh — behind Caddy with auto-TLS.

Step 1 — Provision the Hetzner VPS

1Create the server
  1. Go to Hetzner Cloud Console
  2. Create a new project (or use existing)
  3. Add a server:
    • Location: Ashburn, VA (closest to US East / IB servers)
    • Image: Ubuntu 24.04
    • Type: CPX11 (2 vCPU, 2 GB RAM) — ~$5–7/month
    • Networking: Public IPv4 enabled
    • SSH Key: Add your public key
    • Name: ib-gateway
  4. Note the public IP address (e.g., 5.78.xx.xx)
The CPX11 (shared vCPU) is sufficient for single-tenant use. Upgrade to CPX21 (3 vCPU, 4 GB) if you need headroom for larger scans.

Step 2 — DNS: Point app.radon.run to the VPS

2Update DNS records

In your DNS provider (Vercel Domains, Cloudflare, etc.):

TypeNameValueTTL
Aapp.radon.run<VPS_IP>300
Important: If using Cloudflare, set the proxy status to DNS only (grey cloud). Caddy handles TLS directly via Let's Encrypt — Cloudflare's proxy will interfere with certificate issuance.
CAA Records: If your domain has existing CAA records (check with dig CAA radon.run), add a CAA record: 0 issue "letsencrypt.org". Without this, Caddy cannot provision TLS certificates via Let's Encrypt.

Verify propagation:

dig +short app.radon.run
# Should return your VPS IP
Set TTL to 300s (5 min) before cutover so you can revert quickly. Increase to 3600 after the migration is stable.

Step 3 — SSH Access & User Setup

3Configure the deploy user

SSH in as root and create the radon service user:

# SSH as root (first time)
ssh root@<VPS_IP>

# Create deploy user
adduser --disabled-password --gecos "" radon
mkdir -p /home/radon/.ssh
cp ~/.ssh/authorized_keys /home/radon/.ssh/
chown -R radon:radon /home/radon/.ssh
chmod 700 /home/radon/.ssh
chmod 600 /home/radon/.ssh/authorized_keys

# Grant sudo for systemctl
echo "radon ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart radon-*" \
  | tee /etc/sudoers.d/radon-deploy
echo "radon ALL=(ALL) NOPASSWD: /usr/bin/systemctl daemon-reload" \
  | tee -a /etc/sudoers.d/radon-deploy

# Install base prerequisites
apt update && apt install -y \
  ufw git curl software-properties-common

# Install Docker (official repo — includes compose plugin)
curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  | gpg --dearmor -o /usr/share/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) \
  signed-by=/usr/share/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" \
  | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# Install Python 3.13 (deadsnakes PPA)
add-apt-repository -y ppa:deadsnakes/ppa
apt update
apt install -y python3.13 python3.13-venv python3.13-dev

# Install Node.js
apt install -y nodejs npm

# Add radon to docker group
usermod -aG docker radon

# Firewall
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw --force enable

Verify:

ssh radon@<VPS_IP> whoami
# radon
Add your local SSH config alias for convenience:
Host ib-gateway
  HostName <VPS_IP>
  User radon
  IdentityFile ~/.ssh/id_ed25519

Never copy the production .env into the application or web tree. post-setup.sh writes a mode-0600 web environment that contains only literal NEXT_PUBLIC_* assignments. Server-only build values are passed directly to the build process by run_with_env.py.

Step 5 — Run the Bootstrap Script

5One-time VPS setup

The full setup is 3 commands from your Mac:

# First run — installs everything, generates SSH key, exits
ssh root@ib-gateway 'bash -s' < scripts/setup-vps.sh

# Add the printed SSH key to GitHub (Settings → SSH keys)

# Second run — clones repos, builds, configures services
ssh root@ib-gateway 'bash -s' < scripts/setup-vps.sh

# Complete setup — env, build, IB Gateway (auto-retry 2FA), services, data, verify
scripts/post-setup.sh
Two-pass setup: On first run, the script generates an SSH deploy key for the radon user and prints it. Add the key to GitHub (Settings → SSH keys), then re-run the same command to continue.

What the script does

  1. Base packages: Installs git, curl, gnupg, ufw, etc.
  2. Prerequisites: Docker CE from official repo, Python 3.13 from deadsnakes PPA, Node.js 22 from NodeSource
  3. Version validation: Verifies all tools are at correct versions
  4. SSH key: Generates deploy key for GitHub access (first run exits here)
  5. Clone repos:
    • git clone git@github.com:joemccann/radon.git ~/radon
    • git clone git@github.com:joemccann/radon-cloud.git ~/radon-cloud
  6. Python venv: Creates ~/radon/.venv, installs requirements.txt
  7. Node build: cd ~/radon/web && npm ci && npm run build
  8. Caddy: Installs from official repos, copies Caddyfile to /etc/caddy/Caddyfile
  9. Systemd: Copies all 7 unit files to /etc/systemd/system/ (root-owned), runs daemon-reload
  10. Firewall: Opens ports 80 and 443
  11. Privileges: Installs fixed deploy helpers and scoped polkit rules; IB Gateway lifecycle commands remain behind the lease-aware control helper
  12. .env validation: Checks required keys exist — skips service startup if missing
Root required: The setup script must be run as root. It creates the radon user, installs system packages, and writes to /etc/systemd/system/.

If the script fails partway, it is safe to re-run — all operations are idempotent.

Step 6 — Configure IB Gateway (Docker)

6Start and verify IB Gateway
# SSH to VPS
ssh radon@ib-gateway

# Start the stack (IB Gateway is started through the 2FA lease gate)
/usr/local/bin/radon start

# Verify container is running and healthy
cd ~/radon-cloud
docker compose ps
docker compose logs --tail 50

Verify connectivity

# Check the configured live (4001) or paper (4002) host port
ss -tlnp | grep -E ':(4001|4002) '

# Test the configured IB API connection without sourcing the secret env file
python3.13 scripts/run_with_env.py .env bash -c \
  'echo > /dev/tcp/127.0.0.1/${IB_GATEWAY_PORT}' && echo "OK" || echo "FAIL"

VNC access (for IB Gateway GUI)

If you need to interact with the IB Gateway GUI (e.g., accept agreements):

# SSH tunnel to VNC
ssh -L 5900:127.0.0.1:5900 radon@ib-gateway

# Connect with any VNC client to localhost:5900
The Docker container image is pinned by digest and Docker auto-restart is disabled. The lease-aware boot helper and API watchdog are the only automated recovery paths. Health checks run every 30s with a 60s startup grace period and select internal port 4001 for live or 4002 for paper. Host port 4001 is bound to loopback and the Tailscale address; host port 4002 is loopback-only. Neither is exposed on the public interface.

IB Gateway 2FA

On first login, IB Gateway requires second-factor authentication. Approve the push notification on the IBKR mobile app. If the 2FA times out:

# This command refuses to cycle the Gateway while another 2FA lease is active.
/usr/local/bin/radon restart
cd ~/radon-cloud && docker compose logs -f

Set VNC_SERVER_PASSWORD in .env to enable GUI access for debugging login issues.

EXISTING_SESSION_DETECTED_ACTION=primary ensures the VPS gateway takes over if another IB session (e.g., local Mac) is active. This avoids the "Existing session detected" dialog blocking headless login.

Step 7 — Start All Services

7Enable and start systemd services

The setup script starts services automatically, but if you need to do it manually:

Step 10 — Set Up CI/CD (GitHub Actions)

10Automated deploys on push to main

Create .github/workflows/deploy.yml in the radon repo:

name: Deploy to VPS
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.VPS_HOST }}
          username: ${{ secrets.VPS_USER }}
          key: ${{ secrets.VPS_SSH_KEY }}
          script: |
            cd ~/radon-cloud
            bash scripts/deploy.sh

Required GitHub Secrets

Set these in the radon repo under Settings → Secrets and variables → Actions:

SecretValue
VPS_HOSTVPS IP address (e.g., 5.78.xx.xx)
VPS_USERradon
VPS_SSH_KEYPrivate SSH key for the radon user

Deploy flow

  1. Push to radon repo main branch
  2. GitHub Actions SSHs to VPS, runs deploy.sh
  3. deploy.sh: git pull → pip install → npm build → restart services → health check
  4. On health check failure: auto-rollback to previous commit
deploy.sh has built-in rollback: if the FastAPI health endpoint (/health) fails after 3 retries, it resets to the previous commit, reinstalls, rebuilds, and restarts services automatically.

Step 11 — Update Clerk & Vercel Configuration

11Reconfigure auth and remove Vercel

A. Update Clerk

  1. Go to Clerk Dashboard
  2. Update allowed redirect URLs to include https://app.radon.run
  3. Add https://app.radon.run to your Clerk application's allowed origins
  4. Remove any Vercel-specific URLs if they're no longer needed

B. Update Next.js config

In radon/web/next.config.mjs, the HSTS header currently only activates when VERCEL=1. Update for self-hosted:

// In radon/web/next.config.mjs — update the HSTS condition:
if (process.env.VERCEL === "1" || process.env.RADON_ENABLE_HSTS === "1") {
  // HSTS header added
}

// Add to your .env on the VPS:
RADON_ENABLE_HSTS=1

C. Remove Vercel deployment

  1. Go to Vercel Dashboard → radon project
  2. Settings → Domains → Remove app.radon.run
  3. Optionally delete the Vercel project or pause it
  4. Remove @vercel/analytics from web/package.json if not using Vercel Analytics

Step 12 — Cut Over: Go Live

12Switch production traffic

Pre-cutover checklist

  • VPS is provisioned and accessible via SSH
  • All 7 services are running and healthy
  • IB Gateway Docker container is healthy on its configured live or paper host port
  • .env is populated with all production secrets
  • Runtime data has been migrated
  • Caddy is serving HTTPS with a valid Let's Encrypt cert
  • https://app.radon.run loads the terminal UI
  • https://app.radon.run/api/ib/health returns healthy
  • WebSocket connects at wss://app.radon.run/ws
  • Clerk authentication works (sign in, sign out)
  • GitHub Actions deploy workflow is configured
  • Rollback has been tested (trigger a failed health check)

Cutover sequence

  1. Lower DNS TTL to 60s (if not already done)
  2. Update A record for app.radon.run → VPS IP
  3. Wait for DNS propagation (dig +short app.radon.run)
  4. Verify HTTPS, auth, and IB data flow in browser
  5. Remove the domain from Vercel
  6. Increase DNS TTL to 3600s

Step 14 — Rollback Plan

14If something goes wrong

A. Rollback to Vercel (full revert)

# 1. Point DNS back to Vercel
#    Update A record for app.radon.run → Vercel's IP / CNAME

# 2. Re-add domain in Vercel dashboard

# 3. Redeploy on Vercel (push to main or trigger manual deploy)

B. Rollback a bad deploy (VPS stays live)

# deploy.sh handles this automatically, but if manual:
ssh radon@ib-gateway
cd ~/radon
git log --oneline -5                     # Find the good commit
git reset --hard <good-commit>
pip install -r requirements-deploy.txt
cd web && npm ci && npm run build && cd ..
sudo systemctl restart radon-nextjs radon-api radon-relay radon-monitor

C. Restart a single crashed service

ssh radon@ib-gateway 'sudo systemctl restart radon-api'
ssh radon@ib-gateway 'journalctl -u radon-api -n 50'
